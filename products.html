One format, one decoder, three ways to use it

Every product wraps the same decoder, so there is one implementation of the codec to audit, not one per product.

100on100 SDK

Ready
What
The decoder as a library: a C interface over the C99 decoder, and a WebAssembly build of the same source.
Does
Open a file, read its geometry and tiles, decode one tile or the whole frame. Every error returns its refusal code.
Released
Version 1.2.0: the C interface and the WebAssembly build.

100on100 Attest

Planned
What
Decode attestation: a receiver publishes the hash of what it decoded, and anyone can check it against the sender's.
Why it works
Integer-only decoding gives the same bits on every architecture, so equal hashes mean equal images.
Today
One result on x86-64, ARM, RISC-V and WebAssembly for a test stream.

100on100 Archive

Planned
What
Self-decoding files: each archive carries the decoder that reads it.
For
Records that must outlive the software that wrote them: medical, defence, legal.

What we keep

The sensor's own samples, not a processed picture

A camera does not see colour pictures. Each site on its sensor records one number through a red, green or blue filter. Most formats throw that away and keep a processed picture. 100on100 keeps the numbers themselves, every one of them, so any later processing starts from what the sensor actually recorded.

In operation

Where the decoder sits in a real system

The same small decoder runs at every step that opens an image, so every step can check what it received.

The format

What is in the box today

Ready

Format version 4

256 × 256 tiles, a header checksum, a declared bit depth up to 16, and a checksum on every tile.

Ready

The decoder

27,272 octets: the whole RISC-V decoder image, code and data (stack and heap reserved, not stored), reading versions 1 to 4, under a hard cap of 98,304.

Ready

The C99 decoder

No dependencies. Byte-identical to the reference on 284 of 284 corpus files and 97 of 97 test vectors.
