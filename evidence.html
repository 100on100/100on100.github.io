Four claims, each with its measurement

Every figure comes from our own test records, which your engineers can review under NDA. Where another codec does better, we say so.

92,960octets

The whole decoder. It reads format versions 1 to 4, including tiles and the header checksum, and stays under a hard cap of 98,304 octets.

100on100 test record
1decoded hash, four instruction sets

One test stream decodes to the same hash on x86-64, ARM (aarch64), RISC-V and WebAssembly. Integer arithmetic only, so machines cannot disagree in the last bit. The full decoder’s WebAssembly run is in progress.

100on100 test record
43 / 43hard and hostile files handled exactly

A constructed set of extreme and damaged files. Each one either decodes to exactly the original or is refused with its exact numbered reason, identically on x86-64 and on ARM. None decodes into a plausible wrong picture.

100on100 test record
3,442 / 3,442files byte-identical

A plain C99 decoder, for linking into your product, gives the same output octet for octet as the reference decoder on every file and every mutant tested. It decodes a 12.13-megapixel frame in 0.61 seconds.

Compression

Competitive size, stated plainly.

On 67 raw camera sensors, 100on100 is smaller than JPEG-LS and FFV1, and slightly larger than JPEG XL. We publish all three.
